# CS 230 Portfolio Reflection

## The Gaming Room Project

The client for this project was The Gaming Room, a company that wanted to expand its existing game, Draw It or Lose It, into a web based application that could support multiple teams and players across different platforms. The software needed to support multiple game instances, maintain unique identifiers for games and teams, and ensure that only one instance of a game could exist at a time. The design also needed to consider operating platforms, memory management, storage, security, and scalability.

## What I Did Well

I think I did particularly well at organizing the information in the software design document and explaining the different technical options available to the client. I considered the advantages and disadvantages of different operating platforms and how they could affect the application's performance and development. I also worked to make the recommendations understandable so that both technical and nontechnical readers could follow the reasoning behind the design decisions.

## Helpful Aspects of the Design Document

Working through the design document helped me understand the importance of planning before writing code. It gave me a chance to identify the application's requirements and think about how different components would work together. Having a plan made it easier to understand what needed to be developed and helped reduce the possibility of overlooking important features.

## What I Would Revise

If I could revise one part of my work, I would improve the level of detail in the system architecture and explain more clearly how the different components would communicate with one another. I would include more specific examples of how the application would handle multiple simultaneous games, manage shared data, and prevent duplicate game instances. This would make the design more useful as a guide during development.

## Considering the User's Needs

I interpreted the client's needs by focusing on the main requirements of Draw It or Lose It, including supporting multiple players, organizing teams, maintaining unique game information, and allowing users to access the application through different platforms. Considering user needs is important because the software must solve the client's actual problem rather than simply function from a technical perspective. Understanding those needs helps developers make better decisions about usability, performance, security, and future improvements.

## My Approach to Software Design

My approach to software design involved identifying the requirements first, comparing possible solutions, and considering the strengths and weaknesses of different technologies before making recommendations. In future projects, I would continue using requirement analysis, diagrams, modular design, and testing plans to organize my ideas before coding. I would also break larger problems into smaller components so that each part could be developed and tested more easily. These strategies would help me create software that is easier to maintain, expand, and adapt to changing requirements.


# CS 305 Portfolio Reflection

## Artemis Financial Project

Artemis Financial was a financial services company that needed help identifying security vulnerabilities in its software and improving the security of its application. The goal was to protect sensitive information, reduce security risks, and ensure that the software used secure communication methods. My work focused on reviewing the existing application, identifying vulnerabilities, and recommending and implementing security improvements.

## What I Did Well

I think I did well at identifying potential security weaknesses and understanding why they mattered. I learned that secure coding is important because vulnerabilities can expose sensitive customer information, damage a company's reputation, and lead to financial losses. Strong software security helps protect customers, build trust, and reduce the risk of costly security incidents.

## Challenges and Helpful Parts of the Assessment

One of the more challenging parts was understanding the vulnerabilities identified by security tools and determining which changes would address them without breaking the application. The process helped me understand that security involves more than finding errors. Developers also need to understand the risks, prioritize issues, and choose appropriate solutions.

## Increasing Layers of Security

I learned that security works best when multiple protections are used together. Examples include secure communication through HTTPS, appropriate cryptographic practices, dependency checks, and reviewing code for vulnerabilities. In future projects, I would use tools such as static analysis tools, dependency vulnerability scanners, and software testing to identify risks. I would also prioritize vulnerabilities based on their severity and the potential impact on users and the organization.

## Ensuring Functionality and Security

To check that the application remained functional, I would run the available tests, build the project, and verify that the application behaved as expected after making changes. I would also rerun dependency checks and review the code after refactoring to look for newly introduced vulnerabilities. This process is important because a security improvement should not introduce new bugs or interfere with the application's existing functionality.

## Helpful Resources, Tools, and Practices

The tools and practices I found useful included Java, the development environment, Maven, dependency checking, cryptographic libraries, and secure coding guidelines. Reviewing scan results and testing the application after making changes helped me understand how security tools fit into the software development process. I can apply these practices in future projects to identify vulnerabilities earlier and create more reliable software.

## Showing My Work to Future Employers

I could show future employers my completed Artemis Financial vulnerability assessment or secure software report to demonstrate my understanding of secure coding, vulnerability identification, and software testing. This project shows that I can examine an existing application, consider security risks, recommend improvements, and document my decisions. These skills are important for software development and cybersecurity roles.
