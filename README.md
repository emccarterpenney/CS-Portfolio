# CS 230 Portfolio Reflection

## The Gaming Room Project

The client for this project was The Gaming Room, a company that wanted to expand its existing game, Draw It or Lose It, into a web based application that could support multiple teams and players across different platforms. The software needed to support multiple game instances, maintain unique identifiers for games and teams, and ensure that only one instance of a game could exist at a time. The design also needed to consider operating platforms, memory management, storage, security, and scalability.

## What I Did Well

I think I did particularly well at organizing the information in the software design document and explaining the different technical options available to the client. I considered the advantages and disadvantages of different operating platforms and how they could affect the application's performance and development. I also worked to make the recommendations understandable so that both technical and nontechnical readers could follow the reasoning behind the design decisions.

## Helpful Aspects of the Design Document

Working through the design document helped me understand the importance of planning before writing code. It gave me a chance to identify the application's requirements and think about how different components would work together. Having a plan made it easier to understand what needed to be developed and helped reduce the possibility of overlooking important features.

## What I Would Revise

If I could revise one part of my work, I would improve the level of detail in the system architecture and explain more clearly how the different components would communicate with one another. I would include more specific examples of how the application would handle multiple simultaneous games, manage shared data, and prevent duplicate game instances. This would make the design more useful as a guide during development.

## Considering the User's Needs

I interpreted the client's needs by focusing on the main requirements of Draw It or Lose It, including supporting multiple players, organizing teams, maintaining unique game information, and allowing users to access the application through different platforms. Considering user needs is important because the software must solve the client's actual problem rather than simply function from a technical perspective. Understanding those needs helps developers make better decisions about usability, performance, security, and future improvements.

## My Approach to Software Design

My approach to software design involved identifying the requirements first, comparing possible solutions, and considering the strengths and weaknesses of different technologies before making recommendations. In future projects, I would continue using requirement analysis, diagrams, modular design, and testing plans to organize my ideas before coding. I would also break larger problems into smaller components so that each part could be developed and tested more easily. These strategies would help me create software that is easier to maintain, expand, and adapt to changing requirements.
